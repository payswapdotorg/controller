CTRL-014 — operator live-test harness

Developer/operator TEST surface only. This page is outside the popup and outside any runtime composition (CTRL-016 scope): it invokes the existing frozen CTRL-014 message boundary (chrome.runtime.sendMessage) against the real installed extension and records deterministic, copyable evidence. It adds no production control, no orchestration, no new recovery semantics, and no provider knowledge — every provider fact stays in the adapter.

Invocations are disabled until the operator acknowledgment above is checked.

Worker

Registered Workers are listed from the extension configuration (GetConfiguration). The service router itself gates the provider — a Worker of the wrong provider fails closed with a typed refusal.

ObserveZaiSession

Typed session observation for the selected Worker (authentication-required / session-missing / ready-for-input / working / waiting / stopped / …).

StartZaiWorkerSession

The governed new-session sequence. The prompt must be the exact Controller-generated governed prompt — the harness carries it verbatim and never authors, rewrites, normalizes, or substitutes it.

0 characters — carried verbatim, never rewritten.

RecoverZaiHungWorker

The existing governed hang recovery: Stop → verified stopped → the fixed message continue → verified acceptance. The tabId must be the exact browser-session correlation the governed start result reported (prefilled from the last successful start; otherwise type it explicitly — it is never guessed).

ZaiOperatorAction — the taught operator capability set

The adapter's operator action surface: state / click / rclick / type / key / eval / navigate / shot — the same primitives the live operator uses, each addressing the exact provider tab below with typed, fail-closed results. The args object is carried verbatim to the adapter (JSON).

SendZaiTurn — launch a prompt into the existing session (CTRL-014 c24)

The resident-supervision turn channel: submit the EXACT governed turn text into the EXISTING provider conversation tab (the operator's "use only the extension to launch a prompt to the agent" directive). The adapter runs the same submission/verification lifecycle and dialog law as Start — without the fresh-session preparation; it never mutates the session registry. The prompt is carried verbatim, never rewritten.

0 characters — carried verbatim, never rewritten.

RelaunchZaiSession — the watcher-died recovery (CTRL-014 c24)

The find-or-open recovery: exactly one provider tab at the session URL is reused (focus + verify + observe); when the tab is gone a fresh tab is opened at the URL and waited to page-ready; popups on the restored surface are dismissed through the bounded key law. An empty session URL addresses the provider home surface. This is the control the operator uses to relaunch the session when the supervision stack dies.

ZaiKeepalive — the extension-side supervision watchdog (CTRL-014 c24)

Arm the watchdog for the supervised provider tab: a periodic alarm checks the tab (gone → automatic relaunch at the armed session URL; page unreachable → counted, then the tab reload; dialog surface → the bounded popup recovery; authentication/verification gates → recorded for the operator, never acted on). Every check lands in the persisted event ring — read it back with Observe.

Evidence log

One deterministic JSON line per invocation: sequence, ISO-8601 timestamp, exact request kind, the request verbatim (including the exact governed prompt), the typed response verbatim, and the tab/session correlation. The log lives in this page's memory only (never persisted, never sent anywhere). No credential or provider token can appear on this surface by construction. Copy it for the Architect review.
